# Performance benchmarks

[reference.json](reference.json) contains the current reference measurements for
304 workload/input combinations: five samples and one excluded warm-up each.
All inputs are generated by tracked scripts. The archive includes the measured
source revision, build and model identities, input parameters, commands, resource
samples and summaries.

## Requirements and build

The runners require Linux, Python 3.11 or newer, Git and GNU `time`.
The commands below also use `taskset` from util-linux. Run from the checkout root:

```sh
nix develop
CARGO_PROFILE_RELEASE_DEBUG=1 cargo build --release
export BINARY="$PWD/target/release/trwl"
export MODEL="$TRWL_SEMANTIC_MODEL_DIR"
export CPUS=0,2
mkdir -p .cache/benchmarks
```

The flake supplies the Rust toolchain, ONNX Runtime and the model pinned in
[flake.lock](../../flake.lock). Set `CPUS` to available CPUs on the machine running
the measurements; the reference uses CPUs 0 and 2 of an Intel Core i5-1235U.
They were not reserved from other processes.

## Import and embedding matrix

```sh
taskset -c "$CPUS" python3 tests/perf.py --binary "$BINARY" \
  --profile reference --model-dir "$MODEL" --repetitions 5 --timeout 120
```

This profile has 88 measured operations:

| Input | Operations | Count |
| --- | --- | ---: |
| OpenCode/Codex × one long/many sessions × 1,000/10,000 messages × 256/4,096-byte bodies | Initial import, unchanged import, three-message append, lexical search, event read | 80 |
| 128 short messages; 32 messages alternating short/long user-reply pairs | Empty-cache embedding fill and query | 2 |
| 100 and 1,000 short messages | Ready semantic query, ready hybrid query, append and query | 6 |

[perf_fixtures.py](../perf_fixtures.py) generates text parts with user/assistant
roles, unique markers and a fixed vocabulary. The many-session shape puts 20
messages in each session. Semantic profiles use one OpenCode session.

The runner checks complete imported text, native identities, duplicates and
surviving IDs. Search and event reads check the selected record and its full text.
Semantic samples restore prepared indexes outside timing; the first query starts
inference, and later queries in that trial can reuse it.

## Long and many-session reads

Generate two text-only inputs with the same message count and body size:

```sh
python3 - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, "tests")
from perf_fixtures import Corpus
for shape in ("long", "many"):
    Corpus(Path(".cache/benchmarks") / shape, Path.cwd(),
           "opencode", shape, 10000, message_bytes=4096)
PY

for shape in long many; do
  taskset -c "$CPUS" python3 tests/perf_history.py --binary "$BINARY" \
    --corpus "$PWD/.cache/benchmarks/$shape/opencode.db" --workspace "$PWD" \
    --query cache --query parser --query timeout --repetitions 5 --timeout 120
done
```

Each input measures 34 operations: import, broad event/grouped searches, query
forms and filters, complete event/session reads, a window, Markdown rendering,
location and all enumeration pages. The long input has one session; the many
input has 500. These inputs isolate session length and count rather than model
tool payloads or natural-language diversity.

## Generated tool-heavy history

```sh
python3 tests/perf_history_corpus.py --output .cache/benchmarks/tool-heavy
python3 tests/perf_history_corpus.py --output .cache/benchmarks/tool-heavy-large \
  --sessions 64 --length-multiplier 2

for corpus in tool-heavy tool-heavy-large; do
  taskset -c "$CPUS" python3 tests/perf_history.py --binary "$BINARY" \
    --corpus "$PWD/.cache/benchmarks/$corpus/opencode.db" \
    --workspace "$PWD/.cache/benchmarks/$corpus/workspaces/project-00" \
    --query cache --query parser --query timeout --repetitions 5 --timeout 120
done
```

[perf_history_corpus.py](../perf_history_corpus.py) generates four Git workspaces,
parent/child session trees, Unicode text, reasoning, tool calls, outputs, errors,
unfinished calls, patches and step records. Eight topics create overlapping
matches. Session lengths cycle through 8, 24, 48, 64, 80, 96, 128 and 256 messages,
then multiply by `--length-multiplier`. The default seed is zero.

The reference's generated inputs have these counts:

| Input | Sessions | Messages | Imported events | Measured operations |
| --- | ---: | ---: | ---: | ---: |
| `tool-heavy` | 32 | 2,816 | 18,733 | 43 |
| `tool-heavy-large` | 64 | 11,264 | 75,701 | 100 |

Each destination must be new. Its manifest records generator/version information,
parameters, row counts, size distributions and hashes. Logical row hashes
normalize the workspace-directory prefix; database hashes include absolute paths
and identify the files from that run.

The history runner checks native parts and complete tool output against the
source, and checks windows, sessions and pagination against full CLI enumeration.
Known literal matches must return results. Phrase and required-word queries use
adjacent source words. Reports distinguish matching, empty and skipped workloads.
Invented text does not establish semantic relevance quality or provider-version
compatibility.

## Long-session updates

```sh
taskset -c "$CPUS" python3 tests/perf_history_updates.py \
  --corpus "$PWD/.cache/benchmarks/tool-heavy-large/opencode.db" \
  --baseline "$BINARY" --repetitions 5 --timeout 120
```

The runner selects the longest session from a copy, prepares its index, then
measures a final-text edit and completion of its last tool. Preparation and
restoration are outside timing. Every trial verifies complete content and order;
warm-up results also have to match a full import.

## Cold and reused inference

```sh
taskset -c "$CPUS" python3 tests/perf.py --binary "$BINARY" \
  --profile semantic-query --sizes 100 --repetitions 1 \
  --model-dir "$MODEL" --keep-data
```

Set `PREPARED_REPORT` to the `report.json` path printed by that command, then run:

```sh
taskset -c "$CPUS" python3 tests/perf_executor.py \
  --prepared-report "$PREPARED_REPORT" \
  --baseline "$BINARY" --candidate "$BINARY" --model-dir "$MODEL" --repetitions 5
```

This measures semantic queries with a cold executor, semantic queries with a
reused executor and hybrid queries with a reused executor. The prepared corpus
has 103 messages after its three-message append. Each query returns three events.
Cold trials stop inference first; reuse trials run an untimed query first.
Filesystem caches are not evicted. Paired outputs must match byte-for-byte.

## Measurement

All commands use fresh CLI processes with automatic indexing and discovery
disabled. Filesystem caches are warm. Fixture generation, correctness checks,
snapshot copying, output compression and process cleanup are outside timing.

- Wall time covers GNU `time` launch through command completion.
- CPU includes command/waited-descendant counters and detached inference-process
  deltas. Detached CPU counters have 10 ms resolution on the reference machine.
- RSS is the command peak plus detached inference processes' lifetime peaks.
  This bounds concurrent RSS; it is not a simultaneous process-tree sample.
  A query after a larger fill can inherit that fill's worker peak.
- Filesystem I/O counts charged storage bytes, not logical reads/writes. Cached
  reads can report zero input. Captured output and GNU `time`'s report are included.

The archive keeps warm-ups separate from the five measured samples. Medians and
ranges describe those five samples. Embedding preparation is separate from ready
query measurements. GPU builds, HTTP inference, cold filesystem caches and
concurrent source writes are not measured.

## Comparing executables

Use `--baseline BEFORE --candidate AFTER` instead of `--binary` for `perf.py`,
add `--candidate AFTER` for update measurements, and provide the two executable
paths to `perf_executor.py`. History reads take one executable per run; use the
same generated input for both.

Paired runners alternate order and exclude a warm-up pair. Compare resource
changes as well as wall time; the [runner's comparison policy](../README.md#comparison-policy)
only classifies wall time. Reference numbers are machine-specific, not portable
thresholds.
